## Outcome
FAILED at `build_image` step, in the **EAS OTA update lane** (Metro bundling during `eas update`). Backend Docker build was unaffected. A failed run is never promoted — the previous healthy run (e4da02d1-...) is still live at https://gta-quest-map.emergent.host.

## Root cause
Metro could not resolve a module import:

```
[expo-cli] Unable to resolve "../hooks/useGameStore" from "app/shootout-simulator.tsx"
Error: Unable to resolve module ../hooks/useGameStore from /workspace/frontend/app/shootout-simulator.tsx
None of these files exist:
  * hooks/useGameStore(.ts|.tsx|.js|...)
  * hooks/useGameStore
```

`frontend/app/shootout-simulator.tsx` line 6 imported `useGameStore` from `'../hooks/useGameStore'`, but no such file exists under `frontend/hooks/` (that dir contains only castleLevelsData.ts, useCastlePhysics.ts, useMapQueries.ts, useRunawayGame.ts, useSoundEffects.ts).

The `useGameStore` hook is actually defined and exported in `frontend/stores/gameStore.ts` (line 72: `export const useGameStore = create<GameState>(...)`). Every other file in the app correctly imports it from `'../stores/gameStore'` (e.g. car-chase.tsx, runaway-simulator.tsx, package-grab.tsx, login.tsx, and the `shootout-simulator.tsx.bak` backup). Only the current `shootout-simulator.tsx` had the wrong path — a regression in that one file.

## Fix (verified in eph sandbox)
In `frontend/app/shootout-simulator.tsx`, line 6, change:

```diff
- import { useGameStore } from '../hooks/useGameStore';
+ import { useGameStore } from '../stores/gameStore';
```

Verified in the eph pod: applied the edit, confirmed `stores/gameStore.ts` exports `useGameStore`, and confirmed no other `hooks/useGameStore` references remain anywhere in `frontend/`. This resolves the unresolved-module error.
