## Outcome
Deploy failed at `build_image`, in the **EAS OTA update lane** (Metro bundling via `eas update`). The Docker/backend lane is not the problem. This is an **app-source** bug, not infra or manifest.

(The `git rev-parse --show-toplevel` warnings above it are harmless EAS noise, not the failure.)

## Root cause (verified in eph sandbox against this run's pulled source)
`frontend/app/shootout-simulator.tsx` line 6 imports the game store from the wrong path:
```ts
import { useGameStore } from '../hooks/useGameStore';
```
No such module exists. `frontend/hooks/` contains only: `castleLevelsData.ts`, `useCastlePhysics.ts`, `useMapQueries.ts`, `useRunawayGame.ts`, `useSoundEffects.ts`.

The store actually lives at `frontend/stores/gameStore.ts`, which exports it:
```
72: export const useGameStore = create<GameState>((set, get) => ({
```
**Every other file in the app** imports it correctly as `'../stores/gameStore'` / `'../../stores/gameStore'` (index, login, car-chase, runaway-simulator, package-grab, battle, etc.). `shootout-simulator.tsx` is the lone regressed file. Notably, the sibling backup `frontend/app/shootout-simulator.tsx.bak` line 6 has the correct import `'../stores/gameStore'`, confirming `.tsx` regressed from a good version.

Line 7 (`'../hooks/useMapQueries'`) is fine — that file exists.

## Fix (single line, Source)
In `frontend/app/shootout-simulator.tsx`, line 6, change:
```ts
import { useGameStore } from '../hooks/useGameStore';
```
to:
```ts
import { useGameStore } from '../stores/gameStore';
```
No other change needed. The named export `useGameStore` already matches.

## Verification
- Reproduced the exact unresolved-module condition by inspecting the pulled source in the eph sandbox: the imported path does not exist, the target `stores/gameStore.ts` does and exports `useGameStore`.
- Note: full Metro bundle was not run end-to-end in the sandbox, but the resolver error is a deterministic missing-file failure; correcting the path resolves it.
