# RCA — Deploy run de0a5bae-d297-4fb1-9648-d721018bdb9c (gta-quest-map)

## Outcome
FAILED at `build_image` step — EAS OTA lane (Metro bundling / `eas update`). Backend Docker lane is not the problem; the whole build fails because Metro cannot resolve a bad import. This is an **app source-code** failure, not a manifest/infra/platform issue.

## Error (from Cloud Build logs)
```
[expo-cli] iOS Bundling failed ... node_modules/expo-router/entry.js
[expo-cli] Unable to resolve "../hooks/useGameStore" from "app/shootout-simulator.tsx"
  6 | import { useGameStore } from '../hooks/useGameStore';
Error: Unable to resolve module ../hooks/useGameStore from /workspace/frontend/app/shootout-simulator.tsx:
None of these files exist:
  * hooks/useGameStore(...)
  * hooks/useGameStore
Error: update command failed.
```
(The `git rev-parse --show-toplevel` lines above it are benign EAS warnings, not the cause.)

## Root cause (verified in eph sandbox)
`frontend/app/shootout-simulator.tsx` line 6 imports from a non-existent path:
```ts
import { useGameStore } from '../hooks/useGameStore';
```
- `frontend/hooks/` contains only: `castleLevelsData.ts`, `useCastlePhysics.ts`, `useMapQueries.ts`, `useRunawayGame.ts`, `useSoundEffects.ts`. There is **no** `useGameStore` there.
- The hook actually lives at `frontend/stores/gameStore.ts`, which exports `useGameStore` (line 72: `export const useGameStore = create<GameState>(...)`).
- Every OTHER file under `app/` (one level deep) imports it correctly as `../stores/gameStore`. `shootout-simulator.tsx` is the sole file with the wrong path — a copy/paste typo.

## Fix (Source — E1 to apply in frontend)
In `frontend/app/shootout-simulator.tsx`, change line 6:
```ts
// from
import { useGameStore } from '../hooks/useGameStore';
// to
import { useGameStore } from '../stores/gameStore';
```
`shootout-simulator.tsx` sits at `app/` (one level under `frontend`), so `../stores/gameStore` is the correct relative path — matching the other `app/*.tsx` files.

## After the fix
Re-trigger the redeploy. No manifest change, secret change, tier change, or DB change is required. Both prior failed runs (459363f5, 75e41d38) and this one share the identical error, so this single edit should clear the bundling failure.
