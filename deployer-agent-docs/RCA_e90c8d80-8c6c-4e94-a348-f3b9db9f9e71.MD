# RCA — Deploy run e90c8d80-8c6c-4e94-a348-f3b9db9f9e71 (gta-quest-map / "Street Legends")

## Summary
The redeploy failed at the **build_image** step, in the **EAS OTA lane** (not the Docker backend lane). The `eas project:init` sub-step runs `expo config --json`, which exited with code 1 because the app config failed **schema validation**. The Docker/backend image itself is fine.

## Failing step
- Envelope `failed_step`: `build_image`
- Real failure location: EAS lane → `[EAS_LOG] Initializing EAS project...` → `eas project:init` → `node_modules/expo/bin/cli config --json exited with non-zero code: 1`
- The `git rev-parse --show-toplevel` message in the log is a **harmless warning** (eas-cli falls back to the working directory). It is NOT the cause.

## Root cause (reproduced + verified in eph sandbox)
`frontend/app.json` configures the `expo-build-properties` config plugin with `android.extraProguardRules` as an **array of strings**. The installed `expo-build-properties` (`~58.0.12`, pulled in by the recent Expo SDK 57→58 upgrade — it is a newly added dependency, confirmed by diffing `package.json.sdk57.bak`) requires this field to be a **single string**.

Exact error captured by running `node node_modules/expo/bin/cli config --json` against the real app.json in the sandbox:

```
ValidationError: Invalid options object. expo-build-properties options object does not match the defined schema.
 - options
 - options.android.extraProguardRules (type): Expected type string, got array
    at validateConfig (.../expo-build-properties/build/pluginConfig.js:609:33)
    at withBuildProperties (.../expo-build-properties/build/withBuildProperties.js:29:59)
    ...
    at getConfig (.../@expo/config/build/Config.js:271:12)
```

Because `getConfig()` throws, `expo config --json` exits 1, which makes `eas project:init` fail, which fails the whole Cloud Build (`build_image`). This was previously valid under the older SDK and only started failing after the SDK 58 upgrade bumped/added `expo-build-properties`.

## The fix (source change — in `frontend/app.json`)
Convert `expo-build-properties` → `android.extraProguardRules` from an array of strings into a single newline-joined string.

Current (broken):
```json
[
  "expo-build-properties",
  {
    "android": {
      "enableMinifyInReleaseBuilds": true,
      "extraProguardRules": [
        "-keep class com.google.android.gms.internal.consent_sdk.** { *; }",
        "-keep class com.google.android.gms.ads.** { *; }",
        "-keep class com.google.android.gms.common.** { *; }",
        "-keep class * extends androidx.room.RoomDatabase { <init>(); }",
        "-keep class * extends androidx.work.InputMerger { <init>(); }",
        "-keep class io.invertase.googlemobileads.** { *; }",
        "-keepattributes *Annotation*"
      ]
    }
  }
]
```

Fixed:
```json
[
  "expo-build-properties",
  {
    "android": {
      "enableMinifyInReleaseBuilds": true,
      "extraProguardRules": "-keep class com.google.android.gms.internal.consent_sdk.** { *; }\n-keep class com.google.android.gms.ads.** { *; }\n-keep class com.google.android.gms.common.** { *; }\n-keep class * extends androidx.room.RoomDatabase { <init>(); }\n-keep class * extends androidx.work.InputMerger { <init>(); }\n-keep class io.invertase.googlemobileads.** { *; }\n-keepattributes *Annotation*"
    }
  }
]
```
(All rules preserved, joined with `\n`. ProGuard reads a newline-separated string identically.)

## Verification
In the eph sandbox I built a minimal project with the real `app.json`, the real `plugins/`, and the SDK-58 plugin packages, then ran `expo config --json`:
- Before fix: exit 1 with the ValidationError above.
- After converting `extraProguardRules` to a newline-joined string: **exit 0, config parsed OK** (`name=Street Legends slug=street-legends`). No other validation errors surfaced.

## Notes / ruled out
- The `react-native-google-mobile-ads` plugin only has `androidAppId` (no `iosAppId`), but that version only `console.warn`s on a missing iosAppId — it does NOT throw, so it is not the cause.
- The two local plugins (`withRemoveMediaPermissions.js`, `withBuildConfig.js`) only register deferred mods; they do not throw during config read.
- This is a frontend source fix (`frontend/app.json`), not a deployment-manifest issue, so the deployer agent cannot patch it. Apply the change in the source environment and re-trigger the deploy.

## Next action for E1
Edit `frontend/app.json`, change `expo-build-properties` → `android.extraProguardRules` from an array to the newline-joined single string shown above, then re-trigger the deployment.
